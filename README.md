# 澄心瑜伽 · 私教全流程管理（体验课测评 / 排课 / 续费 / 转教练交接）

城市瑜伽馆私教业务的一体化页面：**会员、顾问、教练** 三个角色围绕 **同一套训练记录** 协作 ——
从体验课预约、教练测评、购课排课，到每节课的课后记录、请假改期、不适上报、**转教练交接** 与续费跟进，
每一次疼痛、缺勤、训练效果和课程调整都会沉淀为后续排课与续费沟通的依据。

- 技术栈：Vue 3 + TypeScript + Pinia + Vue Router + Vite（纯前端 SPA，数据存 localStorage，可一键重置演示数据）
- 项目类型：前端（无后端业务接口，故不提供 Swagger/OpenAPI）

## 快速启动

### 方式一：Docker（一键）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

也可手动：`docker build -t yoga-pt-studio . && docker run -p 8080:80 yoga-pt-studio`

### 方式二：本地开发

```bash
npm install
npm run dev        # http://localhost:5173
```

### 生产构建与预览

```bash
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # http://localhost:4173
```

## 转教练交接（本题核心流程）

状态机：`待新教练确认 → 试运行中 → 待顾问决定 → 已稳定转入 / 已结束-不适配`

1. **顾问发起**：会员认为当前教练风格不合适（可在「请假与申请」提交换教练申请生成工单，或顾问主动发起）→
   顾问在「转教练交接」或工单一键进入发起页，页面**自动整理训练目标、已完成课程、疼痛变化、会员偏好与投诉原因**，
   顾问补充交接说明并按目标匹配选择新教练。
2. **新教练确认**：新教练登录后在周课表看到交接提醒，进入交接页**阅读完整交接记录**（目标/课后记录/疼痛趋势/偏好/专业档案），
   确认接手后进入试运行 —— 课包、排课与待上课程转到新教练名下，历史记录不从零开始。
3. **试运行跟踪**：会员在主页多次打卡**满意度**；第一节课结束后新教练填写**首课适配反馈**（适配/基本适配/不适配）；
   顾问在看板与交接详情页同时跟踪会员满意度与新教练反馈。
4. **顾问决定**：反馈适配 →「稳定转入」；仍不适配 → 页面给出**退课 / 转团课 / 换目标方案**建议
   （退课与转团课会结束课包并取消剩余待上课程，换目标方案则课包继续、重新对齐目标）。
5. **沟通记录**：顾问/教练/会员三方在交接档案中的留言全程保留，流程完结后仍可追溯；关联的换教练工单随流程自动办结。

## 验证方式（建议演示路径）

1. **体验转化**：顾问登录 →「安排体验课」为李敏选教练（介意异性 → 仅显示女教练，按目标推荐）→ 教练苏晴/林岚登录 → 周课表点体验课 → 填课后记录 → 填测评（体态评估/动作限制/课程建议/风险提示/推荐套餐，提交即锁定）。
2. **购课排课**：会员张倩登录 → 主页确认购买推荐套餐 → 自动生成课包、每周排课、请假规则与续费提醒基线。
3. **上课记录**：教练林岚登录 → 周课表点王晓彤的待上课 → 填完成动作/体感/疼痛变化/家庭练习 → 下节课重点自动同步。
4. **转教练交接（完整闭环）**：
   - 顾问陈曦 →「转教练交接」看到孙悦的流程（待新教练确认），点入可查看自动整理的交接资料；
   - 教练苏晴登录 → 周课表顶部「转教练交接」→ 阅读交接记录 →「确认接手」→ 孙悦的待上课程转到苏晴名下（首课重点变为试运行首课）；
   - 苏晴完成首课（周课表点孙悦的课填课后记录）→ 回到交接页填**首课适配反馈**；
   - 会员孙悦登录 → 主页打卡**满意度**、给顾问/教练留言；
   - 顾问陈曦 → 交接详情页看到满意度与适配反馈 → 决定「稳定转入」（工单自动办结）；
   - 若反馈不适配：页面提示建议**退课 / 转团课 / 换目标方案**，选择后按对应规则处理课包，双方沟通记录保留在交接档案中。
   - 另可从「异常工单 → 更换教练」或「转教练交接 → 发起」为何静等会员发起新流程（发起页自动汇总训练目标/已完成课程/疼痛变化/投诉原因）。
5. **异常闭环**：
   - 会员王晓彤 →「请假与申请」上报膝盖不适 → 教练林岚在会员档案中做「课程调整」→ 顾问在「异常工单」办结；
   - 教练周远在周课表点「请假」→ 顾问在工单中为何静的课改期补课。
6. **续费**：顾问登录 → 看板「续费提醒」→ 进入赵磊的会员 360° →「基于训练记录生成要点」（出勤、疼痛趋势、教练备注，而非只看剩余课时）→ 保存跟进；选「已续费」则新课包自动衔接。
7. **边界**：顾问在会员 360° 看到的教练专业档案为只读锁定卡（🔒），不可编辑；教练的测评与风险提示不会变成销售话术。
8. 右上角「重置演示数据」可随时恢复初始场景。

## 目录结构

```
src/
  types/index.ts        # 领域模型（预约/测评/课包/排课/记录/工单/续费/转教练交接/时间线）
  data/seed.ts          # 演示种子数据（覆盖六类异常场景 + 进行中的转教练交接）
  stores/               # Pinia：auth（登录）+ data（全部业务动作与看板计算）
  views/
    member/             # 预约体验课、我的主页（课包/课表/购课/转教练满意度打卡）、训练记录、请假与申请
    coach/              # 周课表（交接收件箱）、会员档案、课后记录、体验测评、转教练交接页
    consultant/         # 经营看板、安排体验课、异常工单、会员 360°、转教练交接（列表/发起/详情）
  components/           # 训练时间线（三方共享）、专业档案（锁定只读）、课包卡、转教练步骤条
```
